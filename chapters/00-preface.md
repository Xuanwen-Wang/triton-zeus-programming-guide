# 前言 {#preface .unnumbered}

Triton Zeus 是面向 Zeus V3 的张量编程环境。开发者使用 Python 描述数据分块、索引、运算和数据依赖，编译器将这些操作映射到设备上的控制、向量、矩阵与数据转换单元。除了计算本身，开发者还需要理解数据放在哪里、采用什么布局，以及多个执行单元何时可以安全地使用同一份数据。

Zeus V3 采用 3D DRAM 近存架构。LDG 为权重与 KV Cache 等数据提供近存存储，矩阵计算通过专用高带宽通路访问这些数据；GDG 和片上 L2 Buffer 承担激活、输出和计算工作集等不同职责。这种数据组织方式贯穿本书的硬件模型、内存管理、矩阵乘和 Attention 实例。

本书既供顺序学习，也供开发时查阅。前半部分从一个 BF16 向量加法建立编程模型，说明 LDG、核间分工、类型、访存和语言接口。后半部分介绍编译与部署、错误定位、资源分析和算子优化，并通过归一化、矩阵乘、融合和 KV Cache 案例展示完整的开发过程。

## 符号与代码约定 {.unnumbered}

`kernel` 指设备侧程序；`program` 指 Triton 逻辑程序实例；`tile` 指一次处理的数据块。矩阵维度使用 `M`、`N`、`K`，分块尺寸使用 `BLOCK` 或 `BLOCK_M` 等名称。区间采用左闭右开形式，例如 `[0, 1024)` 包含 1024 个元素。容量采用二进制单位：1 KiB = 1024 B，1 MiB = 1024 KiB。

正文统一使用 **LDG** 表示近存数据存储。代码中的 `memory_type="weight"`、`"kcache"`、`"vcache"` 以及 SDK 的 `kind` 参数保留接口原名。它们描述具体访问或布局契约，不应仅凭名字判断数据能否修改。

代码采用英文标识符与注释。标为“片段”的代码用于说明局部操作，完整程序位于随书 `examples/` 目录；命令中的相对路径以本指南工程根目录为起点。公式和图中的分块尺寸服务于对应例子，调整尺寸时应重新检查索引、存储预算与接口约束。

## 适用范围 {.unnumbered}

本版面向 Zeus V3 单设备的 Triton 算子开发。并行机制按核内和核间组织，多卡通信与推理框架调度仅说明其接口边界。硬件图表达编程可见的数据通路，容量、频率和封装参数以配套产品规格为准。随书示例对应的组件版本、实际执行过的检查及其适用范围见附录与工程验证记录。
